# UI/UX review: HACTU8 console and lab consoles (2026-11-23)

Branch `ui-review` (from `phase1-agx-merge` at `bfd24f0`). This review covers the main
console (`spikes/iac-prototype/iac-host`: Learn, Run, Results, Reports, Registry,
Settings, and the live MCP lab on Run) and the shared lab console
(`demos/_template/web`, which every lab copies).

## How it was checked

- The console was built with `VITE_HACTU8_API_URL=http://127.0.0.1:8020` and served by
  `python -m hactu8.api` on port 8020. Labs AGX01 (5521) and LLM01 (5522) ran from
  `vulnerable_app.py`, and a copy of AGX01 with the old web files ran on 5523 for the
  before shots. Every server was stopped at the end.
- Pages were walked in Chrome with Claude in Chrome. The window could not be resized
  (`resize_window` left it at 814 px), so each page was loaded in a fixed-size iframe:
  1440 px wide (scaled down) for desktop and 400 px for phone. The UI has a dark
  theme (the default) and a light theme (`prefers-color-scheme: light`). Light mode was
  checked by applying the light media rules directly.
- Checks were overflow measured in the DOM (elements past the viewport or container),
  WCAG contrast of every text node against its solid background, Tab order and focus
  rings, disabled and hardware-gated backends, empty, loading and error states, and
  long model names.
- Only the echo backend was run: one LLM01 run from the console and the AGX01 full
  sequence. Ollama was used only to list models. Nothing was pulled.

## Reported issue: model field wider than its space

**Cause, main console.** On the Run page the setup column is 280–340 px wide, and
`.form-grid` split it into two columns for Backend and Model. A native `<select>`
sizes itself to its longest option. The Local tier lists
`basalt (needs an NVIDIA Blackwell GPU)`, which made the backend select 285 px. That
pushed the model select to x=724 when the form ends at x=580, so the model select
was 144 px past the panel edge (see `console-run-picker-before.png`).

**Cause, lab console.** `.backend-bar` was a flex row, so the backend select took
its width from the `(needs …)` option (336 px at 1440). The model input then got
whatever width was left, and the row wrapped unpredictably at mid widths.

**Fix.**

- Console (`Console.tsx`, `index.css`): Backend and Model now sit in a new
  `.picker-stack`, one full-width row each, with the label above the control. Every
  `.run-form` select and input has `box-sizing: border-box`, `width: 100%`,
  `min-width: 0`, `max-width: 100%` and `text-overflow: ellipsis`. A long model name
  or a `(needs …)` option can no longer widen the control.
- Lab console (`demos/_template/web`): `.backend-bar` is now a single-column grid with
  a Backend row, a Model row, then a `.backend-actions` row holding the
  **Use backend** button and the note. The controls use the same sizing rules, so a
  long model name such as `mistralai/ministral-8b-2512:…q4_K_M` shows an ellipsis
  inside the input.
- After the fix, the lab, backend and model controls all end at x=561 inside a form
  that ends at x=580, in every tier (Offline, Local, Aggregator). At 400 px nothing
  overflows.

## How the lab consoles are kept in sync

There was no sync script. The 49 lab `web/` folders were byte-identical hand copies
of `demos/_template/web`. `scripts/vendor.py` now also vendors
`demos/_template/web/{index.html,app.js,styles.css}` into every `demos/*/*/web/`, and
`--check` reports drift (528/528 match). To change a lab console, edit the template,
then run `python scripts/vendor.py`.

## Suggested, not done

1. **Run page skill blurb.** The description is the SKILL.md trigger text ("Use when
   the user wants to run, script, or explain…"). It is written for agents and reads
   oddly to people. Add a short human summary to the skill metadata.
2. **Availability list wording.** `no server at http://localhost:8080 (URLError)`
   exposes the Python exception name. Map it to plain text ("not running").
3. **Heading consistency.** Run, Reports and Settings use an h1 page heading. Results
   and Registry use a small h2/h3 in the side column. Use one page-heading pattern.
4. **Registry on phone.** Picking an entry should scroll to the detail. Registry
   still uses inline styles from the older prototype (`sharedStyles.ts`); moving it
   to `index.css` classes would make it themeable like the rest.
5. **Theme toggle.** `ThemeProvider` supports a `terminal` theme, but no control sets
   it, and light mode only follows the OS. Either expose a toggle or drop the dead
   theme.
6. **Header logo in light mode.** The light-grey logo mark is faint on the light
   header. A light-mode logo variant would fix it.
7. **Lab console backend row at desktop.** The full-width select is 1150 px at 1440.
   Capping the control (for example `max-width: 640px`) would read better, if a
   narrower row is acceptable.
8. **Segmented tier control at 280 px.** "Aggregator" only just fits. Consider two
   rows or shorter labels if more tiers are added.
